# One field renamed, 12/10/2026 (Morpholog v0.0.15)

`IDENTITY-DESIGN.md` is frozen and cites the programme it was frozen with,
`identity-register.morph` at hash `sha256:312e6e56…`. Those bytes are
unchanged in git at `ff44771` and remain the programme the sponsor approved.

Morpholog v0.0.15 adds a `check --strict` hint (#532): a field or parameter
name the generated Python client would refuse. The register named one field
of `LinkProposed`, and the matching parameter of `propose_link`, `class`, a
Python keyword, so `generate python-client` would refuse the programme and
`scripts/check-programmes` (which checks strictly) failed.

The field and the parameter are now `link_class`, in four places (the
predicate, the transformation's parameter list, its `admit`, and one comment).
Nothing else changed. The design's mapping table names `LinkProposed`'s
arguments by position (`#exact / #previous_name`, `#candidate`) and never by
this name, so no part of the design reads differently. The route report is
unchanged: 14 invariants, every one compiled, every one's cases `bound`.

The pin `PROGRAMME_HASH.json` moved from `sha256:312e6e56f3c9bb3a466679828199e2213f85529ed4af6c97c17af7ff1d87257c`
to `sha256:bd4da45a58176b7f57a063b152a14b64d17162b4c02e7e80e6a77097461456a9`.
Nothing is built, deployed or recorded, so no record was ever written under
the old hash.
