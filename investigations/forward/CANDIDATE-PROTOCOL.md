# Forward Mysteries — candidate generation and killing, Generator v4

**Frozen 2026-08-26, after Batch 01 completed under v3 and before any
Batch 02 candidate was generated.** Supersedes v3 (`CANDIDATE-PROTOCOL-v3-
superseded.md`, digest `ab45edbe72961374801f72677bbc74e1953aa9380341c904
cd7b1e2ed40535c6`), preserved byte-exactly. Two edits were made to the
draft of the same day before freezing, both recorded in Part A (P1, P3);
nothing else changed. **Further changes wait for a completed Batch 02.**

v4 is a **patchset**, not a new generator. Batch 01 showed v3's generation
logic — force → necessary function → current absorber — working: the
incumbent guess was right in 10 of 10 rows, the candidates were real
functions with real buyer classes, and v3 surfaced blind (C10) the family
that later consumed two commissioned studies. What failed was
experimental design: **eight of ten candidates froze a symptom that the
proposed public instrument could not observe**, and the scoring rule
counted that blindness as signal.

The batch also corrected what the generator *is*. Ten correct incumbent
guesses against one measured absorption failure says v3 is good at
finding **forced functions and their current homes**, and that commercial
white space is far rarer than forcing variables. v4 therefore treats the
generator as a **forced-function generator**, owning the first arrows of
`external change → forced function → current absorber → absorption
failure? → externalisation? → capture?`, and the funnel as the instrument
that discovers whether a forced function becomes an investable
opportunity. The market decides the later arrows; the generator is not
asked to. Every change below traces to a recorded
lesson (`LESSONS-PENDING.md`) and the candidate that produced it. Anything
not listed in Part A is carried from v3 unchanged.

## Part B — the v4 protocol text

### §1 Generation — carried from v3 unchanged

Blind generation from public structural change, used only to establish
that a required function grows. Force vocabulary as v2/v3. Bias toward
two or three co-present externalisation forces. No incumbent-market
evidence, no buyer evidence, no instrument values before freeze. The
generator produces, per candidate: the function; the forces; the
incumbent that would absorb it; the predicted strain symptoms; and the
cheap forcing observation — exactly the v3 row.

### §2 Revealed strain — carried from v3 unchanged

The marginal cost of absorption is measured by revealed strain (rising
prices, lengthening queues, falling quality, rapid hiring, triage,
internalisation, emergency automation, standardisation pressure,
liability failures, entrant-attracting margins), never by input counts.

### §3 Pre-freeze Instrument Gate — new (P1, P2, P8)

Run on every candidate **after generation and before the batch is
frozen**, by someone who does not read the series' values. For each
predicted symptom, record:

1. **Existence** — the exact public series: publisher, dataset or document
   identity, URL, cadence, licence. "Regulator reporting" is not a series;
   "Ofgem DSO Incentive Report, annual, PDF, table X" is.
2. **Population resolution** — does the series identify the population the
   candidate is about, or aggregate it away? (C10: MHCLG major-application
   types do not distinguish data centres.)
3. **Observability** — is the field observed and published, or would it
   have to be inferred? (C8: turnaround inferred from triage dates is not
   observed.)
4. **Earliest observable date** — from the mechanism's own timetable, when
   can the symptom first exist? If after the investigation horizon,
   record the date. (C2: M1 due dates from late 2027; resolving metric
   1 Feb 2027.)
5. **Risk-bearing** — if the symptom is a third party's price or appetite,
   does that party bear the risk the function manages? (C4: insurers
   exclude degradation; the price cannot move.)

Guidance (P8): against a free public incumbent, declare service-level
symptoms. Guidance (L6, carried): name the scarce unit of work.

The gate assigns one **instrument state** per candidate (the best state of
any of its symptoms):

- **eligible now** — at least one symptom passes all five checks today;
- **eligible later (date D)** — passes 1–3 and 5; fails 4 with a named
  date; kill deferred to D, candidate retained in the batch;
- **proxy only** — no symptom passes, but a declared proxy passes 1–3 with
  a stated inferential gap; the gap is written into the kill record before
  the kill runs;
- **no viable public instrument** — nothing passes. The candidate is
  **not removed from the commercial funnel**: it is frozen with this state,
  runs K0 like every other candidate, and only if it passes K0 is it
  quarantined — as **"buyer-real, not publicly strain-testable"**, recorded
  with the observation that would resolve it and the party that holds it
  (L7/L8 form: "resolved by measurement M, held by party P"). A candidate
  that fails K0 is killed, whatever its instrument state. Instrument
  quarantine suspends K1/K2, never K0.

**The gate does not inspect answers.** It reads schemas, table headings,
metadata pages and publication calendars. Metadata pages are pinned by
digest in the batch's evidence manifest; the values behind them are not
opened until the kill.

**Substitute symptoms — hard constraint.** When a symptom fails the gate,
a substitute is permitted only if all of the following hold, and the
batch file records each:

1. the **original predicted symptom** is preserved verbatim, with the check
   it failed and why;
2. the **substitute** is derived from the same pre-generated force → symptom
   causal chain, with the derivation written out ("because Y");
3. the substitute is **selected and frozen before any values from a
   candidate-specific outcome series are inspected** — by the same
   metadata-only reading as the gate itself;
4. the function, forces and incumbent are unchanged.

If no substitute satisfies all four, the state is *no viable public
instrument*. **The candidate is not rescued.** A "measurable proxy" found
after learning what is going on is hindsight, and the record must make it
impossible to present one as a substitute.

### §4 Freeze — carried from v3, extended

The batch file records, before any kill: every candidate; the evidence
used only to justify generation; force tags; instrument state and the
named series per symptom (from §3); the kill order (ascending cost of
observation, K0 first for all); and the quarantines (adjacency, as v3;
no-instrument, from §3). Nothing is added, removed or reordered
afterwards. The batch file's digest is the experiment.

### §5 K0 — Buyer Reality — new (P3)

First kill after freeze, **for every candidate not quarantined for
adjacency — including those with no viable public instrument**. K0 asserts
only that the function has an economic owner today; externalisation and
capture are later questions. Evidence must be dated and primary (a
mandate, a job specification, a procurement, a budget line, a licence
condition, a code obligation with a date). One of:

- **A. External spend exists** — named buyers pay identifiable third
  parties for the function or its nearest neighbour.
- **B. Internal spend exists** — an **identifiable budget or function
  owner** demonstrably employs people, systems, consultants or operational
  processes specifically to perform it. "Companies employ people who sort
  of deal with this" does not pass.
- **C. Hard obligation** — a dated regulation, contract, market rule or
  operational requirement forces an identifiable budget owner to perform
  it within the horizon.

Not evidence: growth of the forcing variable; "will become important";
"companies will probably need this"; a provider's existence
(`ProvisionExists ≠ ProvisionPurchased`, F001). None of A/B/C → **K0
kill**, recorded with the class that came closest.

Recorded alongside, not as a gate: is the spend **recurring**, or **large
and repeatable across buyers or projects**? For the commercial objective
one of the two must eventually be true; it is scored at K3, not here.

### §6 K1 absorption and K2 strain — v3's kill, with reasons attached (P4, P6, P7)

One research act — the frozen forcing observation — with two answers
recorded separately.

**K1 — Absorption.** Who already gets paid to perform the function; has the
function *already left* the incumbent, and when (P6); is absorption
economically stable as the forcing variable grows (absorber's revealed
investment, cost per unit, capability trajectory)?

**K2 — Strain.** Does the frozen series show the predicted symptom moving,
after the source's own caveats are read and quoted (P7), and after
ordinary-engineering or transition confounders are separated (L1, L4, L9)?

The verdict carries its reason:

- `measured stable` — the series can contain the failure and does not
  show it, or the absorber's revealed investment is ahead of the load;
- `measured strain` — the series shows the symptom, monotone or
  acknowledged by the incumbent, confounders separated;
- `unmeasured — unpublished (party P holds series S)` — the gate's state
  was *proxy only* or the proxy failed; the resolving observation is named;
- `unmeasured — instrument ineligible` — the gate erred; recorded against
  the gate, not the candidate;
- `not yet observable (date D)` — deferred, with the date.

A candidate may not sit in an *unmeasured* state accumulating research.
It is deferred to a date, or quarantined with its resolving observation.

### §7 K3 — Capture — carried from F001, placed explicitly

Only for `measured strain`. Three propositions, earned separately: the
problem is coming; a buyer is compelled to solve it; existing solutions
are inadequate for *that buyer's decision at that time* (`AdequateFor`,
F001 Amendment 4). Plus the four-outcome classification (white space /
category emergence / workflow transition / efficiently served) and the
promotion ban `FounderAttention ≠ InvestorCapital ≠ BuyerSpend ≠
RepeatBuyerSpend`. Recurring-or-repeatable spend (§5) is assessed here.

### §8 Scoring the batch — funnel, not hit rate (P5)

Reported for every batch, quarantines shown separately:

| stage | count |
|---|---:|
| generated | n |
| quarantined — adjacency (K0 not run) | |
| instrument: eligible now / eligible later / proxy only / none | |
| K0 buyer-real (A / B / C) — run on all non-adjacency candidates | |
| quarantined — buyer-real, not publicly strain-testable | |
| K1 absorption inadequate (including *already externalised* named as late) | |
| K2 strain measured | |
| K3 capturable | |

Two numbers are pre-declared per batch and scored:

- **generator quality** = (K1 inadequate or K2 measured strain) ÷
  candidates that reached a *measured* verdict;
- **instrument quality** = candidates reaching a measured verdict ÷
  candidates that passed K0.

The conversion rates are what accumulate across batches and are always
reported: P(buyer-real | generated), P(absorption failure | buyer-real),
P(measured strain | absorption failure), P(capturable | strain).

Thresholds are declared in each batch file before its kills run, as v3
did; v4 sets none here. Retired: "evidenced or plausible ≥ k".

### §9 Everything else — carried from v3

Kill order by ascending observation cost; adjacency quarantine; the
false-negative log; vector forecast scoring; publication posture; the
rule that the next revision waits for a completed batch.
